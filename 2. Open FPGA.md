# What is Open FPGA
Developing a new FPGA traditionally requires large teams of hardware and software engineers and can take months or even years. OpenFPGA addresses this challenge by providing an open-source framework that automates FPGA fabric generation and significantly reduces development time.

---
## Why OpenFPGA?
### Traditional FPGA Development
Developing a custom FPGA typically involves:
- Hardware architects
- Hardware engineers
- Software engineers
- FPGA CAD tool development
- Physical design and verification

The entire process often requires:
- Significant engineering resources
- Complex design flows
- More than a year of development effort

---
## How OpenFPGA Helps
**OpenFPGA** is an open-source framework that enables rapid generation of custom FPGA fabrics tailored to specific applications.
### Key Benefits
- Automates FPGA architecture generation
- Reduces FPGA development cycles from years to days
- Provides open-source CAD tools
- Enables rapid prototyping of custom FPGA architectures
- Supports architecture exploration for domain-specific applications

## Features of OpenFPGA
### FPGA Fabric Customization
- Provides a library of FPGA architecture templates.
- Includes more than 20 FPGA architecture XML descriptions optimized for different applications.
### Automatic FPGA Generation
- Generates Verilog netlists describing complete FPGA fabrics.
- Uses VPR (Versatile Place and Route) architecture description files as input.
### Custom Architecture Design
- Allows designers to create their own FPGA architectures using OpenFPGA's architecture description language.
- Supports architecture exploration and optimization.
### Automated Verification
- Automatically generates Verilog testbenches.
- Validates the correctness of generated FPGA fabrics.
- Reduces manual verification effort.
### Open-Source Toolchain
- Freely available for research and development.
- Encourages FPGA architecture innovation and experimentation.

# Inside FPGA Architecture
<img width="1476" height="1098" alt="image" src="https://github.com/user-attachments/assets/58944eaf-292f-46e9-8208-21d69a041b55" />

## 1. Programmable Fabric
The programmable fabric is the main part of an FPGA and consists of:
- **I/O Banks** – Interface with external signals.
- **Logic Tiles** – Implement combinational and sequential logic.
- **Block RAM (BRAM)** – On-chip memory for data storage and buffering.
- **DSP Blocks** – Dedicated arithmetic units for multiplication, filtering, and signal processing.

## 2. Configuration Circuitry
Configuration circuitry programs the FPGA during startup.
- Loads the configuration bitstream.
- Configures logic blocks, routing resources, and I/O behavior.
- Often uses a scan-chain-based programming mechanism.

## 3. Configurable Logic Block (CLB)
The CLB is the primary computational unit of an FPGA.
- Contains multiple Logic Elements (LEs).
- Performs combinational and sequential logic operations.
- Connected through local routing resources.

## 4. Logic Element (LE)
A Logic Element is the basic building block of a CLB.
Typical components include:
- Lookup Tables (LUTs)
- Flip-Flops (FFs)
- Multiplexers (MUXes)
- Adder circuitry
- Carry-chain connections for arithmetic operations

## 5. Connection Block
Connection Blocks link logic resources to the routing network.
- Connect CLB inputs and outputs to routing channels.
- Enable programmable signal paths.

## 6. Switch Block
Switch Blocks provide routing flexibility within the FPGA.
- Connect horizontal and vertical routing tracks.
- Allow signals to travel across the FPGA fabric.
- Enable communication between logic resources.

## 7. Tile Architecture
A tile is the basic repeating unit of the FPGA fabric.
Each tile typically contains:
- A Configurable Logic Block (CLB)
- Connection Blocks
- A Switch Block

# VTR Flow
# VTR (Verilog-to-Routing) Design Flow

VTR is an FPGA CAD toolchain that converts a Verilog design into an FPGA implementation and evaluates how it maps onto a target FPGA architecture.

---

## Inputs

### 1. Verilog Design

A synthesizable RTL design such as:

- Counters
- FSMs
- ALUs
- Processors

### 2. FPGA Architecture File

An XML file describing the target FPGA:

- Logic blocks
- Routing resources
- I/O structure
- BRAM and DSP resources

---

## VTR Flow
<img width="1422" height="1072" alt="Screenshot 2026-06-16 115608" src="https://github.com/user-attachments/assets/a654b743-919b-4a61-bf75-78bcdd04ba85" />

### Stage 1: Synthesis (Odin II)
Converts Verilog RTL into a technology-independent netlist.
**Functions:**
- Verilog parsing
- RTL synthesis
- Netlist generation
**Tool:** Odin II

### Stage 2: Logic Optimization (ABC)
Optimizes the synthesized netlist and maps it to FPGA logic resources.
**Functions:**
- Logic optimization
- Boolean simplification
- LUT mapping
**Tool:** ABC
  
### Stage 3: Place and Route (VPR)
Maps the optimized design onto the FPGA architecture.
**Functions:**
- **Packing:** Groups logic into CLBs
- **Placement:** Assigns blocks to FPGA locations
- **Routing:** Connects blocks using routing resources
- **Timing Analysis:** Verifies timing requirements
**Tool:** VPR (Versatile Place and Route)
---
## Flow Summary

```text
Verilog Design
      │
      ▼
   Odin II
 (Synthesis)
      │
      ▼
     ABC
(Optimization)
      │
      ▼
     VPR
(Pack → Place → Route → Timing)
      │
      ▼
 FPGA Implementation
```

The `.blif` file represents the digital circuit to be mapped onto the FPGA.

It is written in Berkeley Logic Interchange Format and contains:

- Primary inputs and outputs
- Combinational logic (AND/OR/NOT gates or LUT equivalents)
- Sequential elements (latches / flip-flops)
- Netlist connections between signals

# FPGA Architecture XML (EArch.xml)
<img width="2174" height="1166" alt="image" src="https://github.com/user-attachments/assets/f90917aa-b35f-42b1-990a-5497c475bb14" />

The `EArch.xml` file defines the FPGA architecture used by VTR/OpenFPGA. It describes the available resources, routing network, and device layout.

---
## Main Sections
### 1. `<models>`
Defines the logical building blocks available in the FPGA.
Examples:
- Adders
- Multipliers
- RAMs
- Custom modules

### 2. `<tiles>`
Defines the physical FPGA resources.
Examples:
- I/O tiles
- CLB tiles
- BRAM tiles
- DSP tiles
  
### 3. `<layout>`
Describes how tiles are arranged on the FPGA.
Includes:
- Device dimensions
- CLB placement
- BRAM and DSP locations
- I/O organization
  
### 4. `<device>`
Contains technology-specific parameters used for timing and area estimation.
Examples:
- Resistance and capacitance values
- Routing characteristics
- Switch properties
  
### 5. `<switchlist>`
Defines the programmable routing switches.
Each switch specifies:
- Delay
- Resistance
- Buffer characteristics
  
### 6. `<segmentlist>`
Defines the routing tracks used for signal propagation.
Includes:
- Segment lengths
- Routing directions
- Connectivity patterns
  
### 7. `<complexblocklist>`
Defines the internal structure of FPGA resources.
Examples:

- I/O Pads
- CLBs
- LUTs
- Flip-Flops
- BRAMs
- DSP Blocks
---
## Architecture Hierarchy
```text
EArch.xml
│
├── Models
├── Tiles
├── Layout
├── Device
├── Switch List
├── Segment List
└── Complex Block List
    ├── I/O Pads
    ├── CLBs
    ├── LUTs
    ├── Flip-Flops
    ├── BRAMs
    ├── DSP Blocks
    └── Clock Resources
```
### Summary
`EArch.xml` acts as the blueprint of an FPGA, describing its logic resources, routing infrastructure, layout, and device characteristics for the VTR/OpenFPGA flow.

# Running VTR (VPR)
The following command runs the VPR (Versatile Place and Route) tool using a specified FPGA architecture file and BLIF design netlist.
```bash
$VTR_ROOT/vpr/vpr \
    $VTR_ROOT/vtr_flow/arch/timing/EArch.xml \
    $VTR_ROOT/vtr_flow/benchmarks/blif/tseng.blif \
    --route_chan_width 100
```
## Command Breakdown
| Parameter | Description |
|------------|-------------|
| `vpr` | Launches the VPR tool |
| `EArch.xml` | FPGA architecture description file |
| `tseng.blif` | Synthesized design netlist in BLIF format |
| `--route_chan_width 100` | Sets the routing channel width to 100 |

## Flow Performed by VPR
After execution, VPR performs:
1. **Packing** – Groups logic into FPGA blocks (CLBs).
2. **Placement** – Assigns blocks to physical FPGA locations.
3. **Routing** – Connects blocks using routing resources.
4. **Timing Analysis** – Evaluates timing and routing performance.

## Output
The command generates reports containing:
- Placement results
- Routing information
- Timing analysis
- Resource utilization
- Critical path delay
