# RISC-V Implementation on SOFA FPGA

## Overview

This experiment focuses on implementing a RISC-V processor on the SOFA (SkyWater Open-Source FPGA Architecture) platform using the OpenFPGA toolchain. The objective is to evaluate how a complete processor design can be synthesized, mapped, placed, and routed onto an open-source FPGA fabric.

RISC-V is an open-standard Instruction Set Architecture (ISA) that has gained significant adoption in academia and industry due to its modularity, simplicity, and extensibility. Implementing a RISC-V core on SOFA provides practical insight into how processor architectures interact with FPGA resources such as logic blocks, routing networks, and configurable interconnects.

Using the OpenFPGA flow, the processor design is transformed from RTL into a hardware implementation through synthesis, technology mapping, placement, routing, and timing analysis. The generated reports provide valuable information regarding resource utilization, performance, and implementation efficiency.

This experiment demonstrates the feasibility of deploying processor-based systems on an open-source FPGA architecture while highlighting the complete FPGA implementation workflow, from architecture definition to functional verification.

# 1. Introduction to RISC-V

RISC-V is an open-standard Instruction Set Architecture (ISA) designed to provide a simple, modular, and extensible processor platform. Due to its open-source nature, RISC-V has become widely adopted in academia, research, and commercial hardware development.

Key advantages of RISC-V include:

- Open and royalty-free ISA
- Modular instruction set extensions
- Easy customization
- Strong ecosystem support
- Suitable for FPGA prototyping and ASIC development

# 2. Why Implement RISC-V on SOFA FPGA?

Implementing a processor on FPGA allows designers to validate processor functionality in hardware before ASIC fabrication.

Benefits include:

- Rapid prototyping
- Hardware validation
- Architecture exploration
- Performance evaluation
- FPGA-based system design

Using SOFA FPGA provides complete visibility into the architecture, enabling detailed analysis of how processor logic is mapped onto configurable FPGA resources.

# 6. Timing Analysis
- To view timing report add constraint file
- Create a `constraints.sdc` file and add the following timing constraints:

```tcl
create_clock -period 200 clk

set_input_delay  -clock clk -max 0 [get_ports {*}]
set_output_delay -clock clk -max 0 [get_ports {*}]
```

### 6.1 Description

- `create_clock -period 200 clk` defines a clock with a period of **200 ns** (equivalent to **5 MHz**).
- `set_input_delay` specifies the maximum delay for all input ports relative to the clock.
- `set_output_delay` specifies the maximum delay for all output ports relative to the clock.

These constraints are used by the timing analysis engine to verify setup and hold timing requirements after placement and routing.

# 8. Testbench for Post-Synthesis Verification

The following testbench is used to verify the functionality of the synthesized RISC-V core after implementation on the SOFA FPGA fabric.

## 8.1 Testbench Description

- Generates a clock signal with a period of 10 ns.
- Applies a reset pulse during startup.
- Instantiates the synthesized `core` module.
- Supports optional SDF back-annotation for post-layout timing simulation.
- Terminates the simulation after 200 ns.

Note: Change path as per your path

## 8.2 Verilog Testbench

```verilog

    reg clk, reset;
    wire [7:0] out;

    core uut (
        clk,
        reset,
        out[0],
        out[1],
        out[2],
        out[3],
        out[4],
        out[5],
        out[6],
        out[7]
    );

    // Uncomment for post-layout timing simulation
    // initial $sdf_annotate(

    // uut
    // );

        clk   = 1'b0;
        reset = 1'b0;

        #10;
        reset = 1'b1;

        #50;
        reset = 1'b0;
    end

    initial #200 $finish;
```
